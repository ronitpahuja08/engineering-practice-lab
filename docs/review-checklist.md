# Review Checklist

## Correctness

- [ ] The implementation matches every acceptance criterion.
- [ ] Boundary and invalid-input behavior is explicit.
- [ ] Tests would fail if the central algorithm were removed or broken.

## Design

- [ ] Names express intent without requiring implementation knowledge.
- [ ] State changes and invariants are easy to trace.
- [ ] Complexity claims match the actual operations used.
- [ ] The change does not introduce unnecessary dependencies.

## Maintainability

- [ ] Public behavior is documented.
- [ ] Tests are deterministic and focused on observable behavior.
- [ ] Tradeoffs and follow-up ideas are recorded in the PR.
- [ ] The branch contains no unrelated changes.
